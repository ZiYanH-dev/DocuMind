# 需求文档

> 版本：v0.2
> 对应代码状态：后端与前端主链路均已实现。

## 1. 产品定位

**DocuMind** 是一个基于个人知识库的 RAG（检索增强生成）问答系统。
用户上传任意资料（PDF / Word / TXT），系统自动解析、分块、向量化后入库；
用户可向 AI 提问，系统基于"用户自己的知识库"检索相关片段并生成带引用来源的流式回答，适用于任意知识场景。

核心价值：
- **回答有据可依、知识私有隔离、对话流畅即时**。

## 2. 目标用户

| 用户 | 典型场景 |
| --- | --- |
| 学生 / 备考者 | 上传课件、教材、笔记，针对难点追问与复盘 |
| 研究者 / 职场人 | 上传论文、报告、制度文档，快速定位与归纳要点 |
| 自学者 | 沉淀个人知识库，随时向 AI 进行"基于资料"的对话 |

## 3. 核心用户故事

1. 作为新用户，我想注册并登录账号，以便保存我的资料与对话。
2. 作为用户，我想上传一份 PDF 教材，系统解析后我能在知识库中检索到它。
3. 作为用户，我想发起一次问答，AI 仅基于我上传的资料作答并标注引用来源。
4. 作为用户，我希望回答是逐字流式出现的，像真人对话一样即时。
5. 作为用户，我想新建 / 查看 / 删除多个会话，分别管理不同主题的讨论。
6. 作为用户，我想删除不再需要的文档或会话，释放空间并清理上下文。

## 4. 功能清单

### 4.1 账号（Auth）

- 注册（用户名 + 密码 + 可选邮箱）
- 登录获取 JWT（`Authorization: Bearer <token>`）
- 获取当前用户信息

### 4.2 文档管理（Documents）

- 上传文档（PDF / DOCX / TXT），自动：
	- 落盘 → 解析 → 分块 → 向量化入库
- 查看文档列表（分页、按当前用户隔离）
- 删除文档（同步删除分块与本地文件）

### 4.3 会话管理（Conversations）

- 创建会话（自定义标题，默认"新对话"）
- 查看会话列表
- 查看某会话的历史消息
- 删除会话（级联删除消息）

### 4.4 流式问答（Chat）

- 发送一条消息，流式返回：
	- 会话 ID → 增量 token → 引用来源 → 结束
- 指定 `conversation_id` 续聊，或留空自动创建新会话
- 自动构建最近 10 条历史作为上下文（多轮记忆）
- Agent 自主判断是否检索，闲聊不查库，知识类提问必查
- 检索范围严格限定在"当前用户的文档"，低相似度片段在 SQL 层被过滤
- 引用来源按文档与分块去重后结构化返回

### 4.5 系统

- 健康检查 `/health`

## 5. 非功能性需求

| 维度 | 要求 |
| --- | --- |
| 数据安全 | 用户间数据隔离（文档 / 会话 / 消息均按 `user_id` 归属与过滤）；密码哈希存储（bcrypt） |
| 检索质量 | 查询改写 + 向量与 BM25 双路召回 + 倒数排名融合 + 重排，最终取 `top_k=4`，向量路阈值 0.3 |
| 响应体验 | 问答采用 SSE 流式推送，首字延迟可控 |
| 可扩展性 | LLM / Embedding 支持 OpenAI、DeepSeek（兼容）、Ollama（本地）多提供方切换；检索各路可单独关闭做对照实验 |
| 可维护性 | 严格五层分层 + 类型注解 + ruff / mypy(strict) + 分层 AST 测试 |

## 6. 范围与边界

**已实现**：
- 后端：账号、文档上传与解析、混合检索、Agent 问答、SSE 流式推送、会话管理、统一响应信封与统一异常处理、三级缓存。
- 前端：登录与注册、知识库页、问答页、SSE 流式渲染、路由守卫。

**规划中**：
- 文档状态轮询（当前上传为同步处理）、异步任务队列、多模态 / 表格解析、引用片段高亮、限流与审计。
- Service 层改抛 `AppError` 子类，摘掉分层测试里的两条 `xfail` 债务。

**明确不做（本期）**：
- 多用户协作共享知识库、文档在线编辑、模型微调、移动端原生 App。
